# 自迭代：流程和产出在哪里起作用

工具箱靠"让模型真的去玩，再把玩出来的东西收回来"变好。这份文档说明这个循环怎么走、每种产出放在哪里、在什么时候起作用。它描述的是流程，具体做法由做的人决定。

## 两个循环

**局内循环**（一局游戏之内，由游玩的模型自己完成）

写任务 → 运行 → 读报告 → 改任务。产出留在玩家项目里：`tasks/`、`queries/`、`notes/`，以及对 `main.mjs` 的修改。它们只对这一局起作用。

**仓库循环**（跨局，由贡献者完成，人或代理都可以）

1. **玩。** 让几个模型各自从模板项目开始，在真实服务器上玩一段时间。
2. **看。** 收集四样：每个玩家项目的 `node report.mjs review`（从 main 自己写的时间线算出的一页）、服务器能证实的事实（死亡、时间）、模型的报告、它们留下的工作区。
3. **归位。** 把发现放到它起作用的地方（下表）。
4. **再玩。** 下一次试玩检验上一次的改动有没有用；没用的改掉或删掉。

## 产出放在哪里，什么时候起作用

| 产出 | 放在哪里 | 什么时候起作用 |
| --- | --- | --- |
| 一句话的提醒 | `game/template/AGENTS.md` | 每一局，从第一步起就在模型上下文里 |
| 有实质内容的专题知识 | 对应的 skill | 模型做到相关的事、去查的时候 |
| 插件或游戏版本的怪行为 | 修复处的注释、`game/lib/plugins.mjs` | 代码运行时自动生效；贡献者升级插件时看到 |
| 好用的控制逻辑（模型写的任务、反射的改进） | `game/experimental/`，附来源和实机记录 | 模板默认接上或模型复制使用 |
| 默认值的调整 | 模板 `main.mjs`、`plugins.mjs` | 每一局自动生效 |
| 看到了什么、依据、现在的做法 | `docs/lessons.md` | 贡献者改设计之前读 |
| 定下来的取舍 | `docs/principles.md` | 同上 |
| 可重复的实机检查 | `game/dev/SCENARIOS.md` 和试验区的记录表 | 每次改了核心、插件或试验区之后 |
| 一次试玩的原始材料（报告、工作区、提示词） | 仓库之外的项目文件 | 下一次试玩对照时 |

判断一条产出该放哪，看它要在什么时候被谁用到：每局都要的进常驻的一页；只在某种情境需要的进 skill；不需要模型记住的直接做进代码和默认值。能做进代码的，优先做进代码。

## 怎样算好用

- **看行为，不看文字。** 一条提醒写进去之后，下一次试玩里同样的失败还出现，就说明它没起作用：换成代码里的默认值或检查，或者删掉。
- **用服务器的记录核对。** 死亡次数、时间以服务器为准；模型的自述用来找原因。
- **数字保持少而固定。** 每次试玩都看同样几项，都来自 `node report.mjs review --json`：死亡次数和原因、第一个作业多久跑起来、第一个自写任务是否一次跑通、首次运行就失败的任务、main 崩溃几次、模型多久没读报告。多少作业因为误解工具箱而失败，要读首次失败的错误行来判断。
- **试验区的东西转为例程** 的条件：在两次试玩中被用到，且没有造成死亡或卡住。

## 现状

2026-11-10 按这个流程走完了一轮（设置和结果在教训文档的"试玩 2026-11-10"一节）。归位这一步顺畅，每条发现都有去处。下面几处还靠临时做法：

- 试玩的布置和提示词保存在仓库之外，没有固定成仓库里的步骤。
- 三个模型各自重写的采集、冶炼、放工作台和熔炉、穿护甲、封闭自己、回到地表、找方块，2026-11-12 对比后各收成一个试验区例程（`digNearby`、`smeltItems`、`placeNear`、`equipArmour`、`sealIn`、`climbToSurface`，查询 `find-blocks.mjs`），每个留下试玩里管用的那种做法，来源写在 [试验区 README](../game/experimental/README.md) 的"每个例程取自哪个版本"；它们合起来示范架构的每个特性（同一 README 的"架构特性对照"）。同时收进的还有玩家提出的报告内容（`upkeep`：工具损坏、饿了没吃的、idle 和反射做过什么）、溺水反射和 main 崩溃后的提示。这些都只在布置的场景里验证过，还没有经过下一次试玩。
- 局内循环只发生在任务文件这一层：三个模型都没有写 `notes/`，也没有改 `main.mjs`。
- 一条改动是否改变了下一局的行为，靠对照前后两局的 `review --json`；这样的对照还没有做过。
