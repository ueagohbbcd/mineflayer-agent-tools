# 理念

这份文档说明工具箱为什么长成现在这样。改设计之前先读它；新的取舍定下来后改这里。每条理念背后的事实在 [lessons.md](lessons.md)。

## 1. 模型看不见游戏

模型只能通过文字和图片知道世界里发生了什么，而且只在它去看的时候才知道。工具箱的第一职责是让"看"便宜、及时、不容易漏：

- 结束工作的每一件事（完成、失败、死亡、被接管）都会唤醒模型，并在报告里写明原因。
- `wait` 返回时附带一份人工选定的短报告：血量、饥饿、离天黑多久、周围的生物、受过什么伤、背包变化。模型没想到去查的东西，靠这份报告送到眼前。
- 更细的事实用查询、地图、截图按需取。

## 2. 模型自己玩

工具箱提供身体和感官，决定由模型做。预先写好的规则只处理来不及等模型的事：秒级的危险（被打、窒息）和没有工作时的生存（还手、吃东西、浮在水面）。其余情况一律结束当前工作、说明原因、交回模型。

工具箱不提供成套的行为库。例程只收实机证明过的小动作，模型用它们拼出自己的任务。

## 3. 核心只做五件事

1. 保持 bot 连接，运行任务文件。
2. 在任务、服务和 idle 之间按顺序交接：同一时刻只有一个控制者。
3. 命令行与常驻进程之间的通信。
4. 唤醒：让 `wait` 返回；没人在等时留一个标记。
5. `wait` 返回时调用已注册的报告函数，拼接文本。

核心不认识 Minecraft：它不引用任何插件，也不知道寻路、战斗、合成是什么。判断核心是否简洁，看的是概念数量和状态数量，而不是行数：一项工作、一个控制者、一套退出流程、一个"接下来做什么"的意图、一个收尾函数。

## 4. 任务守约定，核心不强行接管

任务是普通的异步函数，直接使用真实的 bot。结束任务的方式只有一种：发出退出信号，停下当前的游戏动作，等任务自己返回。约定是一句话：**每次 `await` 之后，如果 `ctx.signal.aborted` 为真就返回。** 工具箱自己的函数都遵守这句话，所以只调用它们的任务不用写退出代码。

不守约定的任务会继续占着角色，核心如实告诉模型，并把重启进程作为兜底。核心不包装、不代理 bot，也不切断任务的调用。

## 5. 唤醒是标记，报告在读的时候生成

唤醒只表示"有事发生"，多次唤醒合并。报告内容在 `wait` 返回的那一刻由各模块现算，所以模型读到的总是当前状态。各模块自己决定报告的格式、增量和去重。

把模型叫醒是 harness 的事：`run` 和 `wait` 是普通进程，harness 在后台命令结束时通知模型。工具箱不调用模型接口。

## 6. 功能模块自治，可以大

观察、地图、渲染、记录等模块各自决定数据放在内存、文件还是数据库，各自写清用法和限制。它们之间通过普通函数调用连接，由 `main.mjs` 这一个文件接线。模块好用就行，体积不是问题。

依赖方向固定：核心 ← 游戏函数库 ← 候选 ← 模板。下层不引用上层。被动的库（根目录、`lib/`）不引用 `game/`，要报告什么由调用方传回调。

## 7. 每件事一种写法

同一件事在仓库里只有一个函数、一个示例、一处说明。第二种写法只有在实机证据表明它在某种情况下更好时才进来。模型学习成本主要来自选择和例外，所以宁可少而确定。

第三方插件的特殊行为集中在一个适配文件里，模板和任务不需要知道。

Mineflayer 生态已有的能力（寻路、战斗、进食、护甲、工具、采集）直接用插件，工具箱只做接线和默认值。

## 8. 默认值保守

默认设置选择最不容易出事的那个，需要更强的能力时由任务显式打开。例如寻路默认只走路，挖掘和搭方块由任务自己开启，任务结束后恢复默认。

## 9. 只认真实验证

- 替身 bot 的单元测试只检查顺序和生命周期。
- 游戏行为（加入、战斗、死亡、合成、插件的实际表现）在真实服务器上验证，结果记在代码旁边的记录表里，写明跑了几次。
- 没验证的写"未验证"，没复现的写"未复现"。
- 模型好不好用，由真实模型试玩回答。

## 10. 进仓库的门槛

| 内容 | 门槛 |
| --- | --- |
| 核心 | 极少改动；每次改动都要说明它属于五件事中的哪一件 |
| 例程 | 先放在候选区；在两次真实试玩中用过且没有造成死亡或卡住，才转为例程 |
| 候选控制逻辑 | 测试或试玩中用到、看起来有用即可；附实机记录 |
| 经验（玩家 AGENTS、skill、教训） | 宽松：有一次真实观察就可以写，标明依据；被后来的试玩否定就删 |

多数后续工作是功能模块和经验的迭代，核心保持不动。
